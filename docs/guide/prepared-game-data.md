# 保護已整理的伺服器資料

主程式原本會在資料過期時重新從客戶端匯出。經過整理或合併的資料可以使用獨立的
`curated-import.json`，讓正常啟動先驗證既有資料，避免自動匯出覆寫人工修正。
這個標記是匯入資料契約，並不把 `export.json` 宣稱為完整原生匯出。

封裝者可呼叫 `Ro3Emu.Setup.PreparedGameData.WriteManifest(dataDir, clientDir)`。
它核對客戶端已驗證的 baseline、release／build／content 識別，以及 Lua、VFS 索引和 protobuf 來源，
再記錄四個靜態資料目錄與 `msgtable.tsv`、`loc_en.tsv`、`export.json` 的完整檔案集合、長度和 SHA-256。
資料庫、金鑰、日誌及其他執行期資料不納入此集合。

啟動時若有標記，來源或資料任一項不符就停止，並保留現有檔案；不會退回自動匯出。
`--reexport` 也不會覆寫這份匯入資料。需要重新匯出時，請先保留原資料，再使用另一個空的資料目錄。
沒有標記時仍沿用上游的匯出流程。

相同來源的標記可以隨資料搬到另一台主機；baseline 不包含機器根路徑或檔案時間。
接收端仍須重新驗證實際來源與資料內容，不能只檢查版本名稱或檔案是否存在。
這個機制依賴受控的資料發布流程，並不代替發布簽章，也不證明已完整還原原服玩法。

對應的 `PreparedGameDataTests` 使用自造檔案與匯出委派，驗證合法匯入、來源與資料失配、
安全路徑、跨目錄搬移及原有流程；測試不執行客戶端 Lua。
