The two PvP scenes' scene-editor monster spawn entries hold `npcId:0`; gameplay entities are chosen at runtime. The implementation therefore uses real player IDs and the lead's CombatService player-target hook, not an invented PvE boss; Dragon Coffin Island's crystals, soul and Fafnir come from its arena script `DungeonLua_3010303` (above). Rank rewards and currency derive from exported config. Kafra rank 1 has `_iAward:0`, so a match result does not fabricate an item grant at that rank. The wire tests override the specialized match sizes only in each isolated host's loaded `GameData` rows to exercise two-player and two-member-faction combat; the shared export and production defaults stay at 100/5 and 30/5. Root owns the CombatService hook, 5013 transport, session/role columns, and routes.

Prontera point entries with an empty `_iRoundMonster` list receive one difficulty-matched configured actor; an activity-only common request serves the refreshed global state. Both are **(inferred)**. Connected-role notification and settlement loops exclude detached activity sessions.

`MG_DB.proto` defines 5003 `DBChickenInfo`, 5071 `DBDragonIslandInfo`, and 5038 `DBOnePieceInfo`. Their saved values are projected on login before the activity unlock sync and after a confirmed settlement. The client DAL full handlers in `LC_DAL_Chicken.lua` and `LC_DAL_DragonIsland.lua` pass maps to the asset layer; the initial packet seeds empty protobuf maps with transient key zero and an immediate increment removes those keys. The zero keys are never saved, offered as a rank/award, or accepted from an RPC. This transport workaround is **(inferred)** from the client's protobuf-to-Lua empty-map behavior and the established `SeasonRefineService` pattern.

The login projections above intentionally run before `ActivitiesReady`; externally callable queue, ready, claim, legacy activity, NPC, and dungeon admissions require the ready flag. Logout clears the in-memory event participation, and a delayed kill or settlement cannot credit a role whose activity session was detached.

The OnePiece 83351 reward preview lists the configured fixed award items with their actual per-item `AwardRestricConfig` limits: 1302000 is capped at 20/day by 1009000, and 1302002 at 5/day by 1009001. `AwardConfig` stores an array of award rows; the source uses `AwardService` for unrestricted group 9101 and a strict fixed-row resolver for restricted group 9201, then commits both and the persisted per-item counters in one `ApplyAwardAsync` transaction. The reward preview uses the 20-clear cap for unrestricted items, an **(inferred)** display maximum. Dragon rank claim uses `AwardService.ResolveDirect` so its fixed grants retain bind/expiry semantics. Dragon 84074 includes a `DungeonResultInfo` snapshot with the real role IDs, factions, and server-confirmed kills. Queue entries expire at window close, readiness expires after 30 seconds, and role departure clears queued or active state. Leaving a fully loaded match eliminates that role and settles only if one faction remains; a departure before all load cancels without rewards. This departure distinction is **(inferred)**.

Kafra's `Lua_CFG_EatChickenLevelConfig.GetRankSurplusPoint` (:145-179) accepts cumulative `iAllRankScore` and subtracts earlier rank limits where `_iUpgradesClear=1`. The source therefore keeps `ChickenScore` cumulative and projects it through wallet item 7; it does not send that score as 5003 `UpdateData[1]`, since `MG_DB.proto` declares `EChickenUpdateDataNum_OutCurrency=6` and leaderboard keys 1053/1054 instead. How match performance produces the configured point/compensation delta and whether higher ranks can drop remain **(inferred)**. The wire test checks the 100-point wallet, durable rank/score, and duplicate-kill refusal.

`PublicParamConfig.DragonIslandCurrency=20000` names a scalar whose server use is unproven; it is not an `ItemConfig` item ID, and `CharacterService.ApplyAwardAsync` rejects a grant of item 20000. The settlement panel and shop tie its earned-currency presentation to item 6, so the source grants item 6 and leaves the 20000 scalar uninterpreted. The Dragon rank panel separately reads `enum_CurrencyType.DragonIslandNetScore=17` (`Lua_GameDefine.lua:5439-5440`; `UI_Sys_DragonIslandWidgetCtrl.lua:1135-1161`). Positive/negative settlement score credits/debits currency 17 in the same transaction as the medal grant and state; treating the exported score delta as this wallet delta is **(inferred)**. The wire test checks a real 80 to 20 loss, persisted debit, and duplicate-kill replay. A pre-existing divergent wallet can prevent a loss debit; the source then records the occurrence without awarding score or medal rather than publish an unpaid rank.
