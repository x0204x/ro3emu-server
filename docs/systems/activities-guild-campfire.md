# Guild campfire, DailyActivity 116

`GuildCampfireService` runs the event inside the guild home (`DungeonConfig` 4000101, gameplay type 7) and serves 83242/83243/83244. Entry is `GuildHomeService`: the client's 32256 GUILD_ENTER_HOME at any hour, one room per guild; 30400 for 4000101 is only the GM tool's path and follows the same rules. It pushes stage changes (83241), a configured lucky-player buff (83240), fruit succession (83245), boss-death/celebration (83247/83246), and finish (83248). Fuel uses owned item costs; the integrated cash-order/payment endpoints explicitly refuse purchases.

Event content (fire, seeds, stages, fuel, fruit, boss) requires current `GuildStore` membership, level 30 from `DailyActivityConfig._iiLv`, function 1321, and `TimedTodoSchedule.IsOpen(116)`; outside the event a visitor sees an empty home. The event attaches to the guild's home room (`GuildHomeService.RoomOf`), which outlives one event: a room only gets stage pushes while the event runs, Finish only after it saw that day's stages 1-4, and its fruit/boss bookkeeping and actors are reset when a day's event first reaches it and at Finish **(inferred)**. Members already inside at 20:00 receive the fire with stage 1; at Finish the fire and seeds leave their view **(inferred)**. The server validates that room, loaded scene, dynamic fire UID, and ten-metre range before an accelerant can change progress. The 32700 seed path validates the dynamic seed UID, interaction id, scene, and `NPCConfig._iInteractDistance` 3.2 metres. This prevents sending either operation from the public map or another guild room.

`CampFireTimeLine` defines the 20:00-20:25 stages. `PublicParamConfig.CampfireFireSeedStage=1` and `CampfireMaxSeedNum=20` put seed collection in stage 1 and cap it per participant. `CampFireSeed` supplies 1/4/10 EXP and `CampFireLevel` supplies the thresholds 25/43/73/159/300. Fuel IDs 1/2/3 debit the exact `CampFireFuel._iItemId` through `CharacterService.ApplyAwardAsync`; their `_iQuality` selects the same seed EXP scale **(inferred)**. Fuel debit and per-guild EXP blob commit in one SQLite transaction. Seed point marks, player counts, and phase draw marks persist per guild/local calendar day, so replay/reconnect and subsequent event days are distinct. The 300-EXP ceiling follows the highest configured level **(inferred)**.
