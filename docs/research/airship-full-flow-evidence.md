## 正常播放與跳過

- `130041` 的 `_kSkip=[2,4]` 支持 4 秒後出現的合法跳過。G 的正常結束與合法跳過共用 action 601／`84011`，封包沒有 skip 欄位；LAB 驗的是這個共用結束、前置及一次性結果，沒有實際點擊跳過按鈕。
- `130031`、`130032` 及 `130161/130162/130163` 的有效 `_kSkip` 為空。已核對的 PC widget 不顯示正常 Skip，Esc 也要求 Skip active。沒有臆造它們的正向跳過路徑；無效退出／錯片尾不會被當作跳過成功。
- G 的五支相關影片 `30031/30041/30161/30162/30163` 已唯讀完整解碼通過，檔案前後 SHA-256 相同。這能排除來源影片解碼錯誤，不能代替遊戲內播放器、3D 故事 `1017`、相機與輸入鎖驗收。

## 重連、重送與獎勵一次性

貨物 UI 重開以 `CompleteNum[1]+1` 選關；第一、二關已提交時重登可接下一關。第三關與發獎同筆提交，提交前失敗保持第 2 關完成值，合法重開仍是第 3 關；提交後未套用記憶體則中止舊角色呈現，重新載入已交付資料。
非零 `83651` 回應在 G 沒有解除 waiting 的專屬 callback；但退出按鈕不受該 waiting 阻擋，關閉會清旗標，重開會讀任務進度。這是來源證據，玩家實際故障恢復仍未驗收。

`83651` 沒有 task、關卡、request id、格子或旋轉資料；前三關內的完全相同空包無法區分「合法下一關」與「重送」。本輪保證目標上限、持久化與不重複發獎，沒有宣稱已恢復原服的解題權威或原始封包去重規則。

QTE grace 內的靜默重連保留模擬器現有 session／attempt，兩個結局仍只能提交一次；這不是已證明原服影片恢復到同一畫格。未完成 QTE 時重啟整個 host，角色回公共返回點，舊 runtime 房間消失，任務保持未完成；舊片尾不能冒領，新入場也不能用舊片尾跳過第一階段。放棄、正式離場與截止時間／片尾競態之後，遲到片尾均不能翻成成功。這四案已實測；原服中斷恢復政策仍為 `UNKNOWN`，無輸入的真實長時間自動逾時仍為 `NOT_RUN`。

已交付 action 141 的正確傳送可重送；其獎勵不會重領。本輪沒有猜造一次性傳送 token，也沒有硬限角色只能從 `1000501` 發請求，因已結算後重登可能在外部仍需補送營地傳送。跨場景旅行的原服重送規則未由 G 證實。

獎勵依原始來源分開：`10103150` 原始 Base EXP 100000；`10103210` 原始 Base EXP 100000；營地 `10104010` 自己的 Base EXP 80000，不能提前併入飛船通關。仍套既有倍率及等級曲線，不另猜 Job 比例。測試用收據、資料庫及累積 EXP（包含升級已消耗量）比對，不以畫面升級當成特定任務的發獎證明。
