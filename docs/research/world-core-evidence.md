# World core implementation and evidence

This page binds the world core implementation (scene admission and AOI, movement and flight, revive, effects, NPC interactions, role operations, team, friends and MG_Common) to static client evidence. Season identity remains `SeasonService.PlayBook = 101`. The work implements authenticated wire exchanges and authoritative state; wire tests do not establish live-client rendering or original-server parity. Citations name files of the decompiled client (under your local `re/` folder), the server protos and the exported `data/config` tables.

## Client decoder boundary: empty name boards

`NW_GameServerHandler.lua:319-329` selects `no_decode_default_array`; `NW_ServerClientHandler.lua:899-952` decodes without a prefilled result. `LC_Scene_Sync.lua:5362-5370` passes 31045 to `LC_SimpleUnit_Manager.lua:509-515`, which immediately evaluates `#datas`. An empty protobuf repeated field can therefore become nil; this is a strong source-based inference, not an observed client crash.

The server sends a **real self entry** when the distant list is empty, after ENTITYSELF has been queued. `LC_SimpleUnit_Manager.lua:509-570,735-771` removes old simple units absent from that snapshot; processing at `:55-112` skips an ID for which `LC_UnitManager.HasUnitOrCached` is true. Self already belongs to the normal unit cache (`LC_UnitManager.lua:1729-1742,3330-3337`). Thus this inferred compatibility encoding clears the last distant board without a fabricated entity or an empty repeated array. The focused wire test checks nonempty initial self, distant player appearance, and self-only replacement after that player changes instance. This has not been confirmed by running the client Lua.

## Explicit inferred policies

These are choices made to satisfy the recovered consumer, not claims of captured original-server behavior. The linked evidence pages enumerate their additional inferences.

- Name boards use floored world cells, preserving signed integer bits for the unsigned proto fields; Lua adds 0.5 to X/Z. Updates and minimap snapshots run every second, bounded to 1000 requested name boards. The self-row empty-list encoding is described above.
- Public admission uses FIFO and `_iRoleCntLimit`, reserves capacity before asynchronous leave hooks, includes loading reservations, reports order without inventing a wait-time estimate, and uses the map entry as its queue identity. Per-session transitions serialize with a released-in-finally gate. Public line enumeration remains a single runtime line. Team enemy aggregation uses same-instance members and their current hatred; it does not disclose targets from a different private instance.
- Flight uses configured `MountFlyMaxSpeed` converted from centimetres per second. Limits are 50 m above ground, 1 m ground tolerance, direction length at most 2, elapsed movement allowance clamped to 0.05-2 s with 1.5 multiplier plus 1.5 m slack; takeoff is capped to one second of flight, free fall to 50 m total/3 m horizontal/1 m upward. Landing resolves against the nav grid with zero remaining fix-land time. This is bounded movement policy, not measured original flight physics.
- Resurrection invitation lifetime is 30 s; `_kDamageParamExtra` entries of type 2 with attributes 101/102 determine HP/SP rates. SP/CD are reserved before reply; an accepted interrupt, another accepted cast, a role change or scene leave invalidates the pending chant. An accepted skill revive stays at the corpse position. Item revive uses the map's flat `[item,count]` tuple; configured-empty costs refuse instead of granting a free revive. Error codes use their recovered localized meaning. Dungeon quota is consumed once per participant on a committed transition.
- 31213 accepts the client's completed-download report only for running task 100 with its exact `[106701,1]` objective, at most once. The login download widget checks local progress=100 before sending; that client report is the inferred trust boundary. The normal 31205 UI delivery remains the single reward owner.
- Custom-data and scene-variable operator commands are explicit testable state producers. Temporary leave accepts 1-600 s and returns to public town 10100; stuck escape uses a 10 s repeat guard. Automatic original encounter triggers are not inferred from these commands.
