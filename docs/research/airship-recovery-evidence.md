# 飛空艇後半流程、獎勵與恢復

副本1000501的演出、戰鬥及結算有不同完成條件。原服成功路徑已確認兩批4+5名登船敵人、首領、戰後旁白與船長收尾；舊有3+3+3波次及五處調查全必點的推定不再適用。

此頁描述協定與持久化規則，不將來源影片、建置或HP=1速殺案例視為完整玩法驗收。完整後端炮擊傷害公式為`UNKNOWN`，完整HP擊沉速度尚未對齊；目前候選玩家端驗收為`NOT_RUN`。

## 中斷與重連必須分開處理

短暫斷線且session仍在寬限期，與整個host重啟失去runtime房間，是不同恢復情況。前者可保留同次attempt；後者不能讓舊片尾套用到新房間。正式離場或放棄也不能靠重新送結局取得通關。

`DungeonTests.AirshipInterrupted`與相關流程案例檢查未完成任務、片尾、重新入場及重送的權威邊界。保留session不等於影片會恢復到相同畫格；原服是否採相同恢復政策仍是`UNKNOWN`。玩家端需另外核對準星、載具狀態、鏡頭、HUD與角色控制。

## 任務獎勵與營地交接

`TaskConfig[10103210]`要求通關1000501，`_kEXP=[1,100000]`為原始Base經驗值，再套用既有倍率。其`_iAward=31321`所選獎勵列沒有額外明示Job經驗值，不能因畫面同時升Base／Job就補造Job比例。

10103220接續自動條件，10104010是營地自己的對話任務，原始Base經驗值80000；不得提前合併進飛船通關。來源需依任務及擊殺分帳，檢查包含升級已消耗量的累積經驗值。

10103210的完成動作`141|10514|1040401|2|10103210|0`經`LC_InteractActions.JumpMapArea`送正式客戶端場景跳轉，落到營地後再接後續任務。這不要求玩家自行按30402退出。服務端檢查已交付來源、完整目的地及參數；相同合法交接重送不重領獎勵。

`LC_CutSceneManager`在故事結束恢復低層UI並執行片尾動作；32709只清過場狀態，不直接完成任務。來源影片看到營地落地，不代表目前候選的載入、對話、獎勵面板及操作鎖均已驗收。

## 耐久通關來源與一次發獎

副本獎勵與原任務通關必須能跨故障恢復。保留既有`DungeonRewardObligation`與收據欄位，以版本1的`dungeon_task_clear_outbox`保存通關來源：

1. `DungeonTaskClearFreezePlan`與原副本獎勵在同筆交易凍結，保存任務ID、StartTime、已完成輪次、目標位置及原始目標。失敗不能留下半筆獎勵或半筆任務事件。
2. 只有對應獎勵`activated=1, completed=1`才可消費。`TaskService.DungeonClears`只推進原任務實例並限制到原需求上限；事後接受、重接或換輪的任務不能借用舊來源。
3. 目標進度、既有`task_followup`及旁表`applied=1`同筆提交。提交前失敗可重試；提交後尚未套用記憶體就中斷，重新登入讀回已提交內容，不能重加目標或重領獎勵。
4. 正常通關及登入恢復都消費未完成義務；原任務後續發獎尚未完成時，不能先發布完成結果。其他副本訂閱者保留原路徑。
5. 舊資料沒有來源快照時維持`UNKNOWN`，不以重登時的現有任務補造來源，也不改寫舊獎勵指紋；目標設定衝突時拒絕套用。

`DungeonTests.AirshipRecoveryAudit`檢查實際協定路徑中的故障、重啟及一次交付；`DungeonTaskClearStoreTests`以自造資料檢查原子回滾、舊來源、快照衝突與旁表權限。測試結果須綁定當次候選及實際執行回報，歷史測試總數不作為新候選已完成的證據。

玩家驗收仍須分別操作正常流程、可用跳過、短斷線、重登、錯誤／重複回報及兩個QTE結局，核對任務進度、Base／Job來源、物品與貨幣只交付一次。上述結果目前為`NOT_RUN`。
