# 飛空艇後半流程與結算恢復證據

本頁核對副本 `1000501` 的登船敵人、首領、戰後調查、船長與墜船 QTE，並記錄任務通關的耐久恢復。
G 的 Lua／匯出配置、LAB 協定測試及玩家畫面是不同證據層。LAB 使用 GM 準備角色、定位及加速擊殺，不能取代原客戶端端到端驗收。

## 任務獎勵與營地交接

G `TaskConfig.lua:44169–44254` 的 `10103210` 目標為通關 `1000501`，`_kEXP=[1,100000]` 是原始 Base 經驗值，再套用伺服器既有任務倍率。
`_iAward=31321` 經群組選到 `AwardConfig 10031321` 空獎勵列，沒有額外的顯式 Job 經驗值。
`10103220` 接著以等級 1 的被動條件自動完成，之後接受 `10104010` 的營地對話任務；後者自己的原始 Base 經驗值為 `80000`，不能提前算成飛空艇發獎。
稽核影片 41:06–09 同時看到 Base／Job 升級，不足以把 Job 升級歸因到 `10103210`；仍須核對同角色擊殺與任務入帳來源，不能臆造 Job 任務獎勵。

`10103210` 的客戶端完成動作是 `141|10514|1040401|2|10103210|0`。G `LC_InteractActions.lua:1383–1401,1411–1489` 將 `JumpMapArea` 轉為 `CLIENT_CUSTOM_JUMP_MAP`，並可先排入新手傳送演出。
這是完成任務後的正式交接，不是要求玩家自己按 `30402` 離開，也不是任意 GM 傳送。
既有 QTE 測試停在 `30403`，`StoryWalkTests` 的 GM 跳點不能證明原客戶端完整執行載入、營地對話與 HUD 恢復。

G `LC_CutSceneManager.lua:788–838` 關閉 CG 面板並恢復低層 UI，`869–890` 在沒有續播動作時送出離開過場狀態，然後執行片尾動作。

影片 40:56–41:11 有載入、營地對話、獎勵與 HUD 恢復；目前伺服器的實機相同行為仍須以原客戶端驗收，不能單靠 Lua 呼叫推定所有操作鎖均已恢復。

## 耐久修復與相容性

原路徑在副本獎勵成功後才透過 `Completed` 呼叫任務通關。若獎勵交易失敗，登入補發只完成副本義務，沒有恢復原通關事件。
有界 LAB 測試曾在 `economy/dungeon-reward` 真正進入交付時注入例外：重啟後副本待領義務清空，但 `10103210` 完成次數仍為 0，證實此缺口。較早未等待交付時點的 SQL trigger 試驗有競態，不能當作恢復證據。

修復保留既有 `DungeonRewardObligation` JSON 與收據欄位，新增版本 1 的 `dungeon_task_clear_outbox`：

1. `DungeonTaskClearFreezePlan` 與原副本獎勵凍結在同一交易寫入旁表；快照包含當下任務 ID、StartTime、已完成輪次、目標位置與原始目標。凍結失敗不會留下半筆獎勵或半筆任務事件。
2. 只有對應獎勵 `activated=1, completed=1` 才能消費。`TaskService.DungeonClears` 只增加原任務實例的對應目標，並以原需求為上限；事後接受、重接或已換輪的任務不會誤用事件。
3. 目標進度、既有 `task_followup` 與旁表 `applied=1` 在同筆普通角色交易提交。提交前失敗可重試；提交後尚未套用記憶體就中斷，重登會讀回已提交的任務及既有後續發獎債務，不重複增加目標。目標已確認但任務發獎尚未完成時，角色下一次進副本前亦可續做債務；未清除前不發布 `30403`。
4. 正常通關在其他 `Completed` 訂閱者與 `30403` 前消費任務旁表；登入也會掃描已交付獎勵但尚未消費的旁表。其他副本完成訂閱者保持原路徑。
5. 舊資料沒有快照時維持 `UNKNOWN`，不以重登時的現有任務補建；不改寫舊獎勵指紋。目標配置改變時拒絕套用並留待核對。

`DungeonTests.AirshipRecoveryAudit` 覆蓋實際飛空艇協定路徑的故障、重啟與一次發獎；`DungeonTaskClearStoreTests` 使用自造資料驗證原子回滾、舊來源拒絕補建、快照衝突及唯讀連線不能確認旁表。
2026-10-29 的精準 LAB 驗證為 **12／12 通過**：獎勵、任務目標及任務發獎三個交易各測提交前與提交後尚未套用記憶體的故障（6 例）；事後接受與重接（2 例）；旁表原子回滾、舊來源與衝突、舊資料庫升級不改原獎勵／收據、二次通關目標防重送（4 例）。
收據欄位相容性測試另有 1／1 通過，欄位清單僅新增新旁表計畫的 28 行，沒有改名或移除既有欄位。
本頁不保存角色個資、正式機紀錄或客戶端配置原檔。測試結果以本次驗證回報為準；原客戶端完整播放、成功／失敗 QTE 操作、載入營地及可操作 HUD 仍為獨立驗收門檻。
