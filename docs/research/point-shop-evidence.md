`ShopConfig` 與 `ShopCommodityConfig` 的完整 literal、defaults 與 metadata 已靜態閉合。有效列分別 35 與 324，與目前 LAB 資料逐欄完全相同。原件 `m_kCount` 的 36／325 是舊宣告，沒有依該數字補列或刪列；商品表另有 18 次同商品 ID 的完整列覆寫，依原件先後順序保留最後一列，並保留覆寫前後證據。

Shop 205 的原始名稱是「試煉商城」，不是公會商城；205、20901、402 沒有普通商品列，不能因截圖上公會分頁存在就替這三個分類創造商品。

原生 `Lua_CFG_ShopConfig.OnInitDatas` 以 shop type、shop ID 建分類群組；`LC_ShopHelper.GetCurrentSeasonOpenedShop` 與 `_checkShopItemSeason` 選擇目前賽季商品分類，`UI_Sys_ShopPanelCtrl.OnSelectShop` 再查 `_iFunctionId`。商品另有 `_iIsLock` 顯示條件、購買條件與時間條件。這些條件要分別核對，不能用「有商品列」推定一定顯示，也不能用缺分頁推定伺服器沒發商品清單。

伺服器沿用上游 `ShopService`：5024 同步購買次數與收藏，82332／82340 處理購買，82338 傳商品時間窗；分頁與商品內容由客戶端配置產生。上游 main `f6d7a2853de1d45fe728d49cc25d8933fc3ae890` 仍使用相同 ShopService，沒有另一組可移植的商城商品補丁。

依 G 的原配置，Base 31 時寵物門檻已滿足，魔物征討、圖騰與競技門檻尚未滿足。LAB 既有 `OpenContent` 預設包含圖騰功能 70122，啟用該政策時可能提前顯示；本輪保留此設定，實際開放狀態以 5056 為準。若 Base 31 缺少寵物分頁，仍需追該次客戶端分類與 5056 資料；不能以正常低等級鎖定解釋所有分頁。此次未發現可證實的後端缺商品或價格缺口，因此沒有強制開放功能、複製商品或改動付款／收據。

`PointShopParityTests` 鎖定上述配置並透過 Bot 核對 Base 31／37／40 的 5056 開放通知、寵物商城真實 82332／5024 管線、500 單價、終身 50 份、SQL 交易故障回滾與重新啟動保留次數。等級與代幣是受控測試準備，不能視為玩家正常取得條件或原生 UI 驗收。精靈之塔的通關 10 樓、7500 價格、賽季一次與重新登入已有 `TowerShopTests` 覆蓋。
